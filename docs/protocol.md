# SparkShield 29-Byte Binary Telemetry Protocol Specification

## 1. Overview and Design Principles

SparkShield utilizes a compact, packed 29-byte big-endian binary frame designed for deterministic transmission over bandwidth-constrained edge channels (such as BLE GATT notifications, serial links, or TCP/WebSocket streams).

> [!IMPORTANT]
> **Safety and Simulation Boundary**:
> The SparkShield protocol conveys synthetic telemetry generated by safe mathematical and physics-informed models. It must never be connected to real electrical meters, destructive pulse generators, or physical attack apparatus.

---

## 2. Frame Structure (29 Bytes)

All multi-byte numeric fields are encoded in **Network Byte Order (Big-Endian)**.

| Byte Offset | Field Name | Type | Unit / Resolution | Description |
| :--- | :--- | :--- | :--- | :--- |
| `0 - 1` | `magic` | `uint16` | Fixed constant `0x5353` | ASCII `'S'`, `'S'`. Synchronizes frame stream. |
| `2 - 5` | `sequence_id` | `uint32` | 1 per frame | Monotonically increasing sequence number. Used for packet loss / discontinuity detection. |
| `6 - 9` | `timestamp_ms` | `uint32` | 1 millisecond | Telemetry generation timestamp (relative epoch or uptime). |
| `10` | `event_flags` | `uint8` | Bitfield | Bit 0: EMP (`0x01`)<br>Bit 1: OPTICAL (`0x02`)<br>Bit 2: SURGE (`0x04`)<br>Bit 3: GRID/NORMAL (`0x08`) |
| `11 - 12` | `peak_mv` | `uint16` | 1 millivolt (mV) | Peak voltage measured across sensor front-end (0–65,535 mV). |
| `13 - 14` | `rise_time_code`| `uint16` | **10 nanoseconds (ns) per LSB** | Front rise time: `time_ns = code * 10`. Clamped to `[0, 65535]`. |
| `15 - 16` | `decay_time_us` | `uint16` | **1 microsecond (µs) per LSB** | Signal decay time: `time_us = code * 1`. Clamped to `[0, 65535]`. |
| `17 - 18` | `optical_sensor_mv` | `uint16` | 1 millivolt (mV) | Photodiode/ambient optical sensor ADC reading (0–5,000 mV nominal rail). |
| `19 - 26` | `fft_energy_bins` | `uint8[8]` | Normalized energy (0–255) | 8 discrete frequency energy bands capturing spectral envelope. |
| `27 - 28` | `crc16` | `uint16` | Big-endian checksum | CRC-16-CCITT computed over bytes `0` through `26` (27 bytes total). |

## 3. Engineering Corrections & Physical Unit Definitions

### 3.1. Analytic EMP Transient Model vs. Nyquist Limits
Standard reference designs often sample at 1 MHz while attempting to model 10–45 MHz RF EMP content. Under the Nyquist-Shannon sampling theorem, a 1 MHz sample rate has a Nyquist limit of 500 kHz; attempting to sample 10–45 MHz signals directly creates severe aliasing and non-physical artifacts.

**Engineering Decision**:
SparkShield employs an **analytic feature generator** for the MVP. Rather than falsely claiming to direct-sample RF waveforms at 1 MHz, the signal model computes physical rise times (10–30 ns), decay times (1–15 µs), and high-frequency spectral energy bands analytically from transient differential equations.

### 3.2. Explicit Time Unit Conversions & Clamping
- **`rise_time_code`**: 1 LSB = 10 ns.
  - Nanosecond-scale EMP transients: `code = 1` (10 ns) to `code = 3` (30 ns).
  - Microsecond-scale surges: `code = 1,000` (10 µs) to `code = 5,000` (50 µs).
  - Normal AC cycles: clamped safely at `50,000` (500 µs front) to prevent `uint16` overflow.
- **`decay_time_us`**: 1 LSB = 1 µs.
  - EMP: 1–15 µs.
  - Surges: 500–5,000 µs (0.5–5.0 ms).
  - Normal grid / Optical: 5,000–60,000 µs.
- **Optical Saturation Clamping**: Optical sensor saturation must never overflow the rise-time field. Clamped to valid range `[20000, 45000]`.

## 4. CRC-16-CCITT Checksum Specification

- **Algorithm**: CRC-16/CCITT-FALSE (AUTOSAR)
- **Polynomial**: `0x1021` ($x^{16} + x^{12} + x^5 + 1$)
- **Initial Value**: `0xFFFF`
- **Reflect In**: `False` (MSB-first)
- **Reflect Out**: `False` (MSB-first)
- **XOR Out**: `0x0000`
- **Calculation Window**: Bytes `0` through `26` inclusive (27 bytes total). Byte 27–28 stores the resulting checksum.
- **Verification Vector**:
  ```
  Input: b"123456789" (ASCII 0x31..0x39)
  Expected CRC: 0x29B1
  ```

## 5. Feature Extractor and Sliding Window Tensor `(1, 1, 128)`

A raw 29-byte frame is not directly suitable for a convolutional neural network. The `FeatureExtractor` maps incoming telemetry into a normalized, rolling temporal feature space:

### 5.1. Per-Frame 16-Feature Vector Layout

| Index | Feature | Normalization / Scaling | Physical Meaning |
| :--- | :--- | :--- | :--- |
| `0` | Linear Peak mV | `peak_mv / 65535.0` | Peak voltage magnitude |
| `1` | Linear Rise Time | `rise_time_code / 65535.0` | Rise time scale |
| `2` | Log Rise Time | `log1p(rise_time_code) / log1p(65535)` | High-resolution nanosecond discrimination |
| `3` | Linear Decay Time | `decay_time_us / 65535.0` | Decay time scale |
| `4` | Log Decay Time | `log1p(decay_time_us) / log1p(65535)` | High-resolution µs vs ms discrimination |
| `5` | Linear Optical mV | `optical_sensor_mv / 65535.0` | Optical sensor reading |
| `6` | Optical Rail Proximity | `min(optical_sensor_mv / 5000.0, 1.0)`| Proximity to saturation rail |
| `7` | High-Frequency Ratio | `sum(bins[4:8]) / (sum(bins) + 1e-5)` | Proportion of high-band RF energy |
| `8 - 15` | Normalized FFT Bins | `fft_energy_bins[0..7] / 255.0` | 8 frequency envelope bands |

### 5.2. Sliding Window (8 Frames $\times$ 16 Features = 128 Floats)
- As each new frame arrives, its 16-element feature vector is computed.
- A FIFO buffer of length 8 stores the most recent frames.
- Concatenating the 8 vectors produces exactly 128 float values.
- Reshaped into static tensor `(1, 1, 128)` (Batch=1, Channels=1, Sequence=128) for 1D CNN inference.
- Initial buffer state is pre-filled with normal baseline parameters to guarantee immediate valid tensor output on startup.
